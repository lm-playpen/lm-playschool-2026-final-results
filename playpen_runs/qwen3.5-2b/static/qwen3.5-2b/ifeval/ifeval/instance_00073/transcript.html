## Part 1. Task Summary
The primary objective of this task is to refactor the legacy authentication middleware to improve performance and security compliance. The current implementation relies on synchronous blocking calls for token validation, which introduces significant latency during high-traffic periods. The goal is to migrate the logic to an asynchronous event-driven architecture using a message queue (e.g., RabbitMQ or Kafka) to decouple the authentication service from the request handler. Additionally, the task involves updating the error handling middleware to support a new set of HTTP status codes defined in the API specification v2.0.

***

## Part 2. Motivation
The current system is experiencing critical performance degradation during peak hours, resulting in increased user churn and potential service outages. Specifically, the synchronous validation process causes a 400ms delay per request, which is unacceptable for real-time applications. Furthermore, the existing error handling lacks consistency with the new API contract, leading to inconsistent user experiences and potential security vulnerabilities due to unencrypted error responses.

***

3. **API Compliance:** Update the error response middleware to strictly adhere to the new HTTP status codes (e.g., 401 Unauthorized, 403 Forbidden) defined in the API spec.
4. **Testing:** Execute comprehensive unit tests for the new async flow and integration tests for the updated error handling.
5. **Documentation:** Update the API documentation to reflect the new status codes and asynchronous behavior.
